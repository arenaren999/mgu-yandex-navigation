# Архитектура и границы совместимости

## Исполнение

MGU Store устанавливает OAP-приложения с `package.json`, JavaScript для Node 8, манифестом SOME/IP и ресурсами RHMI. В этой поставке используется npm-совместимый `.tgz` с префиксом `package/`, собственным ID `aren_yandex`, entry point `javascript/app.js` и явным `mguHmi: ["ID7"]`.

Публичный runtime idrive7-apps обслуживает OnlineApp, жизненный цикл и четыре RHMI-состояния: карта, результаты поиска, меню, подтверждение удаления ключей. Окно не является браузером. Предыдущий HTML/JavaScript API прототип сам по себе установить как OAP было нельзя.

`require('oap-sdk')` остаётся внешней зависимостью: Store документирует подготовку SDK из штатного BMW donor на головном устройстве. В пакете нет SDK, firmware, native SOME/IP bindings или сгенерированных на чужом автомобиле интерфейсов. Сборка на компьютере завершена; связывание с реальным SDK и регистрация RHMI ожидают автомобиль.

В `mgu-repo.json` дополнительно описана сборка исходников через Python. Для первой установки поставляется готовый USB-каталог схемы 2, с размером и SHA-256 пакета. Store прочитал этот каталог и архив своими настоящими JS-модулями на стенде. Зависимости каталога — deploy 0.8.27 и uplink 0.7.13; это выбранная проверенная по исходникам база, не утверждение о минимуме для каждой функции.

## Данные и отображение

| Компонент | Источник | Обработка |
|---|---|---|
| Позиция | `de.bmw.infotainment.navigation.positioning.Positioning`, `Main_Instance`, `currentLocation` | Только валидные числовые latitude/longitude; свежесть до 10 с |
| Скорость | `Vehicle2`, instance `1`, `statusCarSpeed2` | Чтение UInt со шкалой 1/64; отдельная свежесть 5 с; не нужна для маршрута |
| Карта | `static-maps.yandex.ru/v1` | HTTPS → ограниченный PNG-декодер → изображение RHMI |
| Поиск | `geocode-maps.yandex.ru/v1` | JSON → до пяти адресов |
| Маршрут | `api.routing.yandex.net/v2/route` | driving → линия, длина, время |
| Клавиатура | Штатный use case MGU | Текст адреса, координат или ключа |

Для GPS используются публично описанные поля, а не подбор смещения CAN. Источник протокола — hud-widgets; автор документировал `currentLocation` на другой машине и прошивке. Это свидетельство существования интерфейса, но не проверка на X6 G06 I_21w12.2-1-4. Недействительный или старый GPS не превращается в фиктивную позицию.

Приложение запрашивает два автомобильных сигнала только на чтение/подписку. Его собственный код не вызывает диагностику, кодирование, управление двигателем или приводами. Общий upstream runtime содержит и другие утилиты; наличие таких файлов не означает, что они используются приложением. Манифест также включает стандартные сервисы OAP/RHMI для работы интерфейса.

По умолчанию рендерер выбирается runtime автоматически; при недоступности совместимого внешнего renderer предусмотрен программный вывод PNG через штатный RHMI. Оба пути включены в пакет, но реальное переключение на MGU ещё не проверено. Контрольный кадр создан тем же `view.draw` и программным Canvas на компьютере.

## Ограничения API

Это отдельный клиент HTTP API Яндекса. В него не встроены APK Карт/Навигатора или мобильный NaviKit. Официальные MapKit/NaviKit ориентированы на мобильные платформы; готового подтверждённого Linux x86-64 SDK для этой MGU-интеграции не использовано.

Внутренний формат координат — `{lat, lon}` в WGS84. Static API/геокодер используют долготу перед широтой; Route API — широту перед долготой. Эти преобразования проверяются тестами. Для линии Static API использован порядок из подробных примеров; итоговое отображение необходимо проверить на живом ответе сервиса.

Карта — растровый снимок, до 650 × 260 пикселей, увеличенный без обрезки атрибуции. Полилиния упрощается до 100 точек для ограниченного URL; точные манёвры по ней не выводятся. Примерный остаток и отклонение более 80 м — расчёт по линии, без привязки к полосе и без обещания навигационной точности. Маршрут обновляется по действию пользователя. Пробки могут учитываться сервисом в оценке времени, но их цветной слой и постоянная актуализация не реализованы.

## Сеть, ресурсы и личные данные

Разрешены только три HTTPS-хоста Яндекса, порт 443, без перенаправлений. Проверка TLS не отключается. Общий таймаут — 12 с, тело — максимум 3 MiB. PNG ограничен размером, CRC и количеством распакованных байтов; большие или неподдерживаемые изображения отвергаются. Поддерживаются grayscale/indexed 1/2/4/8 bit, RGB/RGBA/grayscale-alpha 8 bit без interlace.

Запрос карты выполняется отдельно от цикла интерфейса. На скрытом экране новые карты не запрашиваются. Ответ для старой цели не заменяет текущую карту/маршрут. HTTP 429 даёт паузу 60 с; другие ошибки карты — 30 с. По умолчанию запросы разделены 15 с; почти неизменное изображение удерживается до 60 с. Ограничение 240 попыток суммарно относится только к текущему запуску и сбрасывается явно или при новом процессе.

Ключи сохраняются в каталоге данных приложения с правами 0600 и заменяются атомарно. На диске они не зашифрованы. История маршрутов и координат на диск этим кодом не пишется. В Яндекс по выбранным функциям передаются ключ, координаты и поисковый текст; собственного облачного посредника и аналитики нет. Изображения и маршрут находятся в памяти. В журналах собственного кода нет ключа, полного URL или содержимого запросов.

Эти ограничения нельзя заменить положительным результатом тестов на компьютере.
